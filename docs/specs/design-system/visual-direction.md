# Visual Direction

## Objective

Translate the existing homepage content spec into a clear visual identity before coding the interface.

## Current Context

- The current app UI is still placeholder-level.
- Homepage structure already exists in `docs/specs/homepage/skeleton.md`.
- Reference sites already exist in `docs/specs/references/`.

## Direction Statement

Status: `Decided`

The homepage should feel:

- Editorial rather than dashboard-like.
- Technical without looking generic SaaS.
- Compact, intentional, and professional.
- Modern, but not dependent on trendy effects.

Primary direction:

- `Hybrid Editorial Technical`

## Visual Principles

Status: `Decided`

- Prioritize strong hierarchy over decoration.
- Use contrast through scale, whitespace, and weight before adding visual effects.
- Keep the homepage fast to scan on first load.
- Let projects and experience feel structured, not card-heavy by default.
- Make the contact path obvious without overusing CTA styling.
- Keep surfaces mostly flat and use dividers, spacing, and typography as the main organizing tools.
- Reserve accent color for interactive states, key labels, and small emphasis moments.

## Reference Analysis To Finalize

Status: `Decided`

Review the existing references and decide:

- Which reference best informs typography.
- Which reference best informs spacing rhythm.
- Which reference best informs homepage flow.
- Which reference elements should be avoided.

Final reference decisions:

- Typography: `santifer.io`
- Spacing rhythm: `santifer.io`
- Navbar and CTA clarity: `zalt.me`
- Homepage flow: `santifer.io`
- Project and experience structure discipline: `jrdan.dev`

Reference patterns to avoid:

- Large floating SaaS cards.
- Heavy gradient hero treatments.
- Overuse of skill logos.
- Over-animated reveals and decorative motion.
- Overly sparse minimalism that hides useful navigation and metadata.

## Candidate Style Axes

Status: `Decided`

Choose one primary direction:

### Option A: Editorial Minimal

- Strong type hierarchy.
- Warm neutral background.
- Dense but controlled content blocks.
- Low chrome, low ornamentation.

### Option B: Technical Portfolio

- Sharper contrast.
- More visible section framing.
- Stronger utility cues for links, tags, and metadata.
- Slightly more system-like presentation.

### Option C: Hybrid Editorial Technical

- Editorial hero and section rhythm.
- Technical metadata treatment in experience and projects.
- Soft background treatment with crisp interface accents.

Chosen option:

- `Option C: Hybrid Editorial Technical`

Reason:

- It matches the current homepage spec better than a pure editorial approach because the site carries real technical metadata, project details, and structured experience entries.
- It avoids the product-marketing feel of a stronger technical portfolio treatment while keeping the site clearer and more useful than a purely narrative layout.

## Brand Adjectives

Status: `Decided`

- Precise.
- Grounded.
- Intentional.

## Forbidden Traits

Status: `Decided`

- Generic SaaS.
- Playful startup branding.
- Dense resume-wall presentation.
